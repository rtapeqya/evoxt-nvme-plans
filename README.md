## NVMe 到底解决什么问题

SATA 通道是机械硬盘时代留下来的接口，理论带宽卡在 600MB/s 左右；NVMe 直接挂 PCIe，单盘顺序读写能到 GB/s 级。纸面之外，更值得关注的是随机小文件的响应，这也是 VPS 上最容易感知到差别的地方。

几个真实会暴露慢 I/O 的场景：MySQL 执行带排序或联表的查询、Docker 拉取和展开镜像、Nginx 在并发峰值时读大量小文件、WordPress 后台点开插件列表。这些操作吃的都是 4K 随机读写，机械盘和普通虚拟盘在这类负载下会直接卡住，CPU 再快也没用。

挑机器时认两样东西：存储写的是 NVMe，虚拟化写的是 KVM。商家页面只写「高速直连」「高性能云盘」而不交代介质和线路的，多留个心眼，因为「SSD 加速」这种说法在实际测试里可能只是拿 SSD 做缓存层，数据库预热之后随机 IOPS 还是会掉下来。

Evoxt 这边有个小细节需要说明：两个第三方价格库对存储介质的写法不完全一致，一个写 NVMe SSD，一个在表格里简写成 SSD。Evoxt 官方套餐页会写明介质，下单前扫一眼那一行，比看任何第三方整理都准。

**NVMe 和普通 SSD 用起来差别大吗？**

价格库的记录有分歧，一个说支持，一个没列。结账页会显示你所在地区可用的付款方式，下单前看一眼就行。
